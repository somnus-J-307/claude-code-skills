# 提示词转换规则

> 从口语化指令到结构化提示词的转换算法
> 日期：2026-05-27

## 核心原则

**保义第一，增强第二。** 转换后的 prompt 必须严格维持用户原意，只做结构化重排和显式化，不补信息（除非用户明确允许）。

---

## 转换流程

```
用户输入
    ↓
① 意图识别（任务类型 + 领域）
    ↓
② 实体提取（角色、任务、格式、约束）
    ↓
③ 模糊检测（哪些信息缺失或模糊）
    ↓
④ 结构化组装
    ↓
⑤ 保义校验
    ↓
输出
```

---

## ① 意图识别规则

### 任务类型判断

| 关键词/模式 | 任务类型 | 适用技术 |
|------------|---------|---------|
| 写、生成、创作、写一篇 | 创意生成 | 角色 + 约束 + Few-shot |
| 分析、评估、比较、对比 | 分析推理 | CoT + 输出格式 |
| 解释、说明、翻译、总结 | 理解转换 | 角色 + 约束 |
| 代码、程序、脚本、函数 | 代码生成 | Few-shot + 输出格式 |
| 设计、规划、方案、策略 | 规划决策 | CoT + 任务分解 |
| 分类、判断、判断是否 | 分类判断 | Few-shot + 角色 |
| 改写、润色、优化、重写 | 文本处理 | 约束 + Few-shot |

### 领域检测

从输入中提取领域信号词：
- 学术：论文、研究、实验、数据、统计
- 技术：代码、API、数据库、部署、架构
- 商业：产品、用户、市场、增长、营收
- 创作：文章、故事、文案、剧本、脚本
- 教育：教程、课程、解释、科普

## ② 实体提取规则

### 角色提取

**输入信号 → 角色设定：**

| 用户说 | 转换为 |
|--------|--------|
| "作为一个XX" / "你是XX" | 保留原角色设定 |
| "帮我写" / "给我" | 不添加角色（除非领域暗示） |
| "用专业的口吻" | 设定为该领域专家 |
| "简单解释给小白听" | 设定为科普者/教育者 |

**原则：** 用户已指定角色时保留，未指定且领域明确时可选添加，未指定且领域模糊时不添加。

### 任务提取

**从输入中分离"做什么"和"怎么做"：**

```
用户输入: "帮我写一篇关于AI的文章，要有趣一点，不要太长"
    ↓
任务: 写一篇关于AI的文章
约束: 有趣、不要太长
```

**模糊任务的处理：**

| 模糊点 | 处理方式 |
|--------|---------|
| 主题不明确 | 保留原样，不补全 |
| 目标受众不明 | 不添加受众假设 |
| 具体输出形式不明 | 使用默认（段落文本） |

### 格式提取

**显式格式信号：**

| 用户说 | 转换为 |
|--------|--------|
| "用表格" / "列表形式" | 输出格式：表格/列表 |
| "写成邮件" | 输出格式：邮件格式 |
| "简短回答" / "一句话" | 输出格式：简短文本 |
| 未指定 | 不添加格式约束 |

### 约束提取

**显式约束信号：**

| 用户说 | 转换为 |
|--------|--------|
| "不要太长" / "简短" | 字数限制：200字以内 |
| "200字左右" | 字数限制：200字 |
| "正式一点" | 风格：正式 |
| "口语化" / "轻松" | 风格：轻松 |
| "不要用术语" | 术语：避免专业术语 |
| 未指定 | 不添加约束 |

---

## ③ 模糊检测规则

### 三级模糊度

**低模糊（直接转换）：**
- 任务明确 + 格式明确 + 约束明确
- 例："帮我用表格对比Python和Java的优缺点"

**中模糊（转换后标注）：**
- 任务明确，但格式或约束部分模糊
- 例："帮我写篇文章" → 任务明确，格式/约束缺失
- 处理：转换后输出，不做假设

**高模糊（需要澄清）：**
- 任务本身模糊
- 例："帮我搞一下那个东西"
- 处理：转换后提示用户澄清

### 不补全原则

**以下信息即使缺失也不自动补全：**
- 目标受众（除非输入中有暗示）
- 具体字数（除非输入中有暗示）
- 输出格式（除非输入中有暗示）
- 专业领域细节（除非输入中有暗示）

**理由：** 补全 = 改变原意。宁可输出一个"不完整但准确"的 prompt，也不要输出一个"完整但偏离"的 prompt。

## ④ 结构化组装规则

### 标准模板

```markdown
[角色]（如有）
你是一个{角色设定}。

[任务]
{从用户输入提取的核心任务}

[上下文]（如有）
{从用户输入提取的背景信息}

[格式]（如有）
{从用户输入提取的输出格式要求}

[约束]（如有）
{从用户输入提取的约束条件}
```

### 组装优先级

1. **任务**：始终包含，这是核心
2. **约束**：用户明确说的约束必须包含
3. **格式**：用户明确说的格式必须包含
4. **角色**：用户指定的角色包含，未指定的不添加
5. **上下文**：用户提供的背景信息包含

### 分隔符使用

- 角色与任务之间：空行
- 任务与约束之间：空行
- 多个约束之间：分号或换行
- 需要强调的部分：`**加粗**`

## ⑤ 保义校验规则

### 校验清单

转换后的 prompt 必须通过以下检查：

| 检查项 | 通过标准 |
|--------|---------|
| 任务一致性 | 转换后的任务描述与用户原意一致 |
| 无额外假设 | 没有添加用户未提及的信息 |
| 约束忠实 | 用户说的约束都在，没说的约束没有 |
| 风格一致 | 转换后的风格与用户期望一致 |

### 校验方法

**逐句对照法：**
1. 读用户原输入，提取每个信息点
2. 读转换后的 prompt，检查每个信息点是否保留
3. 检查是否有新增的信息点（应该是"无"）

**反向验证法：**
1. 只看转换后的 prompt，能否推断出用户原来说了什么？
2. 如果能推断出用户没说的信息，说明补全过度

## 转换示例速查

| 用户输入 | 转换后 |
|---------|--------|
| "帮我写篇文章" | 你是一个写作者。请写一篇文章。 |
| "用专业口吻分析这个方案" | 你是一个专业分析师。请分析以下方案：{方案内容}。请从专业角度进行分析。 |
| "简单解释一下量子计算" | 你是一个科普作者。请用简单易懂的语言解释量子计算。避免使用专业术语。 |
| "帮我写个Python爬虫" | 你是一个Python开发者。请编写一个Python爬虫程序。请提供完整可运行的代码。 |
| "对比A和B" | 请从以下维度对比A和B：{维度}。请以对比表格形式输出。 |
| "不要太长" | （添加到约束中）控制在200字以内。 |
