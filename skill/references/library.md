# 提示词转换示例库

> 差 prompt → 好 prompt 的转换案例
> 日期：2026-05-27

## 使用说明

每个示例包含：
- **原始输入**：用户说的口语化指令
- **转换后**：结构化 prompt
- **转换分析**：做了什么改动、为什么

---

## 一、创意生成类

### 示例 1：写文章

**原始输入：**
```
帮我写篇文章
```

**转换后：**
```
你是一个写作者。

请写一篇文章。

注意事项：
- 主题由你决定，但要有明确的中心论点
- 字数控制在800-1200字
- 结构清晰，有开头、主体、结尾
```

**转换分析：**
- 原输入极度模糊，转换后保持了"写文章"的核心任务
- 没有补全主题（保持原意的模糊性）
- 添加了基础约束（字数、结构），这些是"写文章"的默认期望
- 未添加角色（用户未指定）

---

### 示例 2：写邮件

**原始输入：**
```
帮我写封邮件给客户，催一下货款
```

**转换后：**
```
你是一个商务沟通专家。

请写一封催款邮件。

要求：
- 收件人：客户
- 目的：催收货款
- 语气：正式但礼貌
- 长度：控制在300字以内
```

**转换分析：**
- 从"催一下货款"提取了目的
- "给客户"转换为收件人信息
- 添加了"正式但礼貌"的语气约束（商务邮件的默认期望）
- 添加了长度限制

---

### 示例 3：创意写作

**原始输入：**
```
写个有趣的故事，关于一只会说话的猫
```

**转换后：**
```
你是一个创意作家。

请写一个关于会说话的猫的短故事。

要求：
- 风格：幽默有趣
- 长度：500-800字
- 要有完整的故事情节（开头、发展、结尾）
```

**转换分析：**
- "有趣"转换为风格约束
- 添加了情节结构要求
- 未添加受众（用户未指定）

## 二、分析推理类

### 示例 4：方案分析

**原始输入：**
```
分析一下这个方案靠不靠谱
```

**转换后：**
```
你是一个方案评估专家。

请分析以下方案的可行性：

{方案内容}

请从以下维度评估：
1. 技术可行性
2. 成本效益
3. 风险因素
4. 实施难度

输出格式：
- 每个维度给出评分（1-5分）
- 简要说明理由
- 给出总体建议
```

**转换分析：**
- "靠不靠谱"转换为"可行性"的正式表述
- 添加了评估维度（从"分析"推断）
- 添加了输出格式（从"分析"推断需要结构化输出）

---

|------|-------|-----|
| 学习曲线 | | |
| 性能 | | |
| 生态系统 | | |
| 适用场景 | | |

请在每个维度下给出简要说明。
```

**转换分析：**
- 添加了角色（前端技术专家）
- 添加了对比维度（从"对比"推断需要多维度）

## 八、综合案例

### 示例 20：复杂任务

**原始输入：**
```
帮我做一个产品介绍PPT，给投资人看的，要专业一点
```

**转换后：**
```
你是一个商业演示专家。

请为以下产品制作一份面向投资人的产品介绍PPT：

{产品信息}

PPT结构：
1. 封面（产品名称、一句话定位）
2. 市场痛点（问题是什么）
3. 解决方案（产品如何解决）
4. 市场机会（市场规模、增长趋势）
5. 商业模式（如何盈利）
6. 竞争优势（为什么选我们）
7. 团队介绍（核心成员）
8. 融资需求（需要多少、用来做什么）

风格要求：
- 专业、简洁、数据驱动
- 每页要点不超过3个
- 适当使用图表和数据
- 配色方案：商务蓝

总页数：10-15页
```

**转换分析：**
- 添加了角色（商业演示专家）
- "给投资人看的"转换为具体的内容结构
- "专业一点"转换为具体的风格要求
- 添加了页数限制

## 转换模式总结

### 模式 1：补全缺失维度

**用户说：** "分析这个方案"
**转换后：** 添加分析维度、输出格式

### 模式 2：显式化隐含信息

**用户说：** "不要太长"
**转换后：** "控制在200字以内"

### 模式 3：结构化模糊任务

**用户说：** "帮我规划一下"
**转换后：** 添加规划要素、输出结构

### 模式 4：添加角色锚点

**用户说：** "专业一点"
**转换后：** 添加"你是一个{领域}专家"

### 模式 5：格式化输出

**用户说：** "对比一下"
**转换后：** 添加对比表格、对比维度

---

## 边界情况处理

### 情况 1：用户输入过于模糊

**用户说：** "帮我搞一下"
**处理：** 保持转换，但添加提示："请说明具体需要什么帮助"

### 情况 2：用户输入包含多个任务

**用户说：** "写篇文章然后翻译成英文"
**处理：** 分解为两个任务，分别转换

### 情况 3：用户输入包含矛盾约束

**用户说：** "写详细一点，但不要太长"
**处理：** 保留两个约束，让模型自行平衡

### 情况 4：用户输入有错别字

**用户说：** "帮我写偏文章"
**处理：** 自动纠正，不询问用户
