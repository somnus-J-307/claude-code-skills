# 日记引导 Skill

当用户想要写日记但不知道写什么时，通过闲聊式提问帮他们梳理一天。

## 触发条件
- 用户说"写日记"、"记日记"、"日记"、"今天过得怎么样"
- 用户感觉不知道该记什么、脑袋空空
- 用户主动调用 `/diary`

## 流程

### 第一步：开场
用轻松的语气打招呼，然后问第一个问题。不要一次问很多问题，一个一个来。

示例：
> 来，今天过得怎么样？随便说说就行。

### 第二步：引导提问（按顺序，每次只问一个）

等用户回答完一个问题后，再问下一个。根据用户的回答适当回应（共情、追问细节），不要机械地跳到下一个问题。

问题顺序：
1. **今天过得怎么样？**（整体感受）
2. **有没有什么开心的事？**（哪怕很小的事也行）
3. **有没有什么烦心事或者遇到困难？**（如果用户说没有，跳过）
4. **今天有没有什么新想法或者学到什么？**（不一定非要是学习，任何想法都行）
5. **有没有什么想对自己说的？**（总结、鼓励、吐槽都可以）
6. **明天有什么打算吗？**（可选，如果用户不想回答就跳过）

注意事项：
- 如果用户某一个问题说了很多，可以适当追问细节
- 如果用户说"没什么"、"不知道"，不要强迫，温和地跳到下一个
- 语气要像朋友聊天，不要像问卷调查
- 适当用"哈哈"、"这样啊"、"确实"这样的口语回应

### 第三步：生成日记

所有问题问完后，把用户的回答整理成一篇日记。

日记格式：
```markdown
# YYYY-MM-DD

## 今天的感受
（用户对整体感受的回答）

## 开心的事
（用户提到的开心事）

## 小烦恼
（如果有提到的话）

## 想法/收获
（如果有提到的话）

## 对自己说
（如果有提到的话）

## 明天
（如果有提到的话）
```

生成后先给用户看，问他们要不要修改。

### 第四步：保存

确认没问题后，保存到：
```
~/Documents/日记/YYYY-MM-DD.md
```

如果当天已经有日记文件了，问用户是要覆盖还是追加。

## 语气要求
- 全中文（代码、文件名除外）
- 像朋友聊天，轻松自然
- 不要太正式、不要像写作文
- 不要评价用户写的内容好坏
- 适当共情，但不要过度

## Token 优化
- 日记用 Markdown 格式，纯文本最省 token
- 不要生成多余的格式或装饰
- 文件名用日期，简洁明了
