# A/B 测试方案：口语化指令 vs 结构化提示词

> 验证项目核心假设：结构化提示词是否比口语化指令更有效
> 日期：2026-05-27

---

## 一、测试目标

**核心假设：** 经过 prompt-transform 转换后的结构化提示词，在任务完成质量上显著优于原始口语化指令。

**验证问题：**
1. 结构化 prompt 是否提升输出质量？
2. 提升幅度有多大？
3. 哪类任务提升最明显？

---

## 二、测试变量

| 变量类型 | 变量名 | 说明 |
|---------|--------|------|
| **自变量** | 提示词类型 | A组：原始口语化指令 / B组：转换后结构化 prompt |
| **因变量** | 输出质量 | 由评估指标量化 |
| **控制变量** | 模型版本 | 统一使用同一模型（如 GPT-4 或 Claude） |
| **控制变量** | 任务类型 | 每个任务同时出现在 A/B 两组 |

## 三、测试用例设计

### 3.1 任务类型覆盖

选取 7 类任务，每类 3 个用例，共 21 个测试用例：

| 任务类型 | 用例数 | 示例 |
|---------|--------|------|
| 创意生成 | 3 | 写文章、写邮件、写故事 |
| 分析推理 | 3 | 方案分析、对比分析、决策分析 |
| 代码生成 | 3 | 写代码、调试代码、优化代码 |
| 理解转换 | 3 | 解释概念、翻译、总结 |
| 规划决策 | 3 | 项目规划、学习计划、策略制定 |
| 文本处理 | 3 | 润色、改写、简化 |
| 分类判断 | 3 | 情感分析、内容分类、优先级排序 |

### 3.2 用例格式

每个测试用例包含：

```yaml
- id: "CG-01"
  task_type: "创意生成"
  original: "帮我写篇文章"
  transformed: |
    你是一个写作者。

    请写一篇文章。

    注意事项：
    - 主题由你决定，但要有明确的中心论点
    - 字数控制在800-1200字
    - 结构清晰，有开头、主体、结尾
  evaluation_criteria:
    - 主题明确性
    - 结构完整性
    - 语言流畅度
    - 内容深度
```

## 四、评估指标

### 4.1 主要指标

| 指标 | 定义 | 测量方式 |
|------|------|---------|
| **任务完成度** | 输出是否完整回答了用户需求 | 0-5 分评分 |
| **质量评分** | 输出的整体质量 | 0-5 分评分 |
| **保义性** | 输出是否符合用户原意 | 0-5 分评分 |

### 4.2 次要指标

| 指标 | 定义 | 测量方式 |
|------|------|---------|
| **结构清晰度** | 输出是否有良好的结构 | 0-5 分评分 |
| **信息完整性** | 输出是否包含必要信息 | 0-5 分评分 |
| **可操作性** | 输出是否可直接使用 | 是/否 |

### 4.3 评估方法

**人工评估（主要）：**
- 3 名评估员独立评分
- 取平均分作为最终得分
- 计算评估员间一致性（Kappa 系数）

**自动化评估（辅助）：**
- 输出长度对比
- 结构化程度（标题、列表、表格的使用）
- 关键信息覆盖率

## 五、执行流程

### 5.1 准备阶段

1. **用例准备**：将 21 个测试用例录入测试系统
2. **模型准备**：统一使用同一模型版本（如 Claude Sonnet 4.6）
3. **评估员培训**：统一评分标准

### 5.2 执行阶段

```
对每个测试用例：
    ↓
① 用原始口语化指令调用模型 → 记录输出 A
    ↓
② 用转换后结构化 prompt 调用模型 → 记录输出 B
    ↓
③ 随机打乱顺序，隐去 prompt 类型
    ↓
④ 评估员独立评分
    ↓
⑤ 收集评分数据
```

### 5.3 控制措施

| 控制项 | 措施 |
|--------|------|
| 模型随机性 | 每个 prompt 生成 3 次，取平均 |
| 评估偏差 | 双盲评估（评估员不知道哪个是 A/B） |
| 顺序效应 | 随机打乱 A/B 输出的呈现顺序 |
| 评估员差异 | 多人评估取平均，计算一致性 |

## 六、数据分析

### 6.1 统计方法

| 分析内容 | 方法 |
|---------|------|
| A/B 组均值差异 | 配对 t 检验 |
| 效应量 | Cohen's d |
| 分类变量 | 卡方检验 |
| 相关性 | Pearson 相关系数 |

### 6.2 结果呈现

**核心输出：**
1. A/B 组在各指标上的均值和标准差
2. 统计显著性（p 值）
3. 效应量（Cohen's d）
4. 各任务类型的提升幅度对比
5. 置信区间

**可视化：**
- 柱状图：A/B 组均值对比
- 箱线图：得分分布
- 热力图：各任务类型提升幅度

### 6.3 判断标准

| 结果 | 判断 |
|------|------|
| p < 0.05 且 Cohen's d > 0.5 | 假设成立，效果显著 |
| p < 0.05 且 Cohen's d < 0.5 | 假设部分成立，效果存在但较小 |
| p > 0.05 | 假设不成立，无显著差异 |

## 七、预期结果

基于文献调研和理论分析，预期：

1. **整体提升**：结构化 prompt 在任务完成度上提升 20-40%
2. **任务差异**：
   - 分析推理类提升最明显（30-50%）
   - 创意生成类提升中等（20-30%）
   - 理解转换类提升较小（10-20%）
3. **保义性**：两组保义性得分应接近（结构化 prompt 不应偏离原意）

## 九、风险与应对

| 风险 | 应对措施 |
|------|---------|
| 评估员一致性低 | 培训 + 重新评估 |
| 模型输出不稳定 | 增加生成次数 |
| 样本量不足 | 增加测试用例 |
| 保义性难以量化 | 增加保义性专项评估 |
